# AIHub 163 물류센터 PPE bbox 클래스 매핑 (실측 기반 추론, 공식 확정 아님)

keypoint와 마찬가지로 공식 클래스 코드표를 확보하지 못해, 실제 이미지에 bbox를
그려서 눈으로 확인하는 방식으로 매핑을 추론했다 (`results/figures/ppe_class_mapping_sample.png`,
프레임 `S2-N1401M04259.jpg`).

## 라벨 zip 구조

`labels/train/.../라벨링데이터_241008_add/5.물류센터.zip` 안에 3개 하위 폴더:
- `3.구조물_비계만` — 구조물/비계만 필터링된 서브셋
- `4.자재및공구만` — 자재/공구만 필터링된 서브셋
- `5.전체` — 전체(사용, 112,363개 JSON)

라벨은 3개 물류센터 촬영지(반도체 클러스터, 인천공항 화물터미널E/E2)를 모두
포함하지만, **원천이미지는 반도체 클러스터(파일명 접두사 S2-N1401/1402/1403)만
다운로드**했으므로 `5.전체` 라벨 112,363개 중 **21,037개만 실제 이미지가 있다**
(나머지는 다른 촬영지 라벨이라 이미지 없이 라벨만 존재 — 학습에 사용 불가).

## bbox 형식

```json
{"annotations": [{"middle classification": "01", "class": "07", "box": [x1,y1,x2,y2], ...}]}
```
`box`는 `[x1, y1, x2, y2]`(좌상단, 우하단 픽셀 좌표). 일부 annotation은
`box: null`(occluded 등 이유로 좌표 없음 — 변환 시 제외해야 함).

## 추론된 매핑

| middle_classification | 추정 대분류 | class | 추정 항목 | 근거 |
|---|---|---|---|---|
| 01 | 안전보호구 | 07 | **안전모(helmet)** | 실측 이미지에서 작업자 머리의 흰색 안전모를 정확히 감싸는 bbox 2개 확인(같은 프레임 내 서로 다른 사람) |
| 01 | 안전보호구 | 02 | **안전조끼(safety vest)** | 작업자 상체(조끼) 부분을 감싸는 bbox |
| 01 | 안전보호구 | 01 | 안전벨트/하네스로 추정 | 고소작업대 위 작업자의 몸통(X자 스트랩 보임)을 감싸는 bbox |
| 01 | 안전보호구 | 04,05,06,08 | 미확인 | 이번 샘플에 해당 클래스 인스턴스 없음 |
| 02 | 중장비 | 17 | 고소작업대/가위리프트 등 중장비 | 큰 리프트 장비 전체를 감싸는 bbox |
| 06 | 구조물 또는 비계 | 31 | 대형 구조물/비계 | 화면 하단 대부분을 차지하는 큰 bbox(다른 샘플, `S2-N1401M00001.json`) |
| 07 | 자재 및 공구 | 38,39,41,45 등 | 그라인더/소화기/각종 자재 | 바닥에 놓인 공구·소화기 등을 감싸는 여러 bbox |

**AIHub 공식 설명(웹에서 확인)에 따르면 이 데이터셋은 7개 대분류
(안전보호구/중장비/구조물/사다리/설치물/비계/자재및공구)를 갖는다 — middle_classification
01~07이 정확히 이 순서로 1:1 대응할 가능성이 높다(01=안전보호구, 07=자재및공구는
폴더명과도 일치). 단, 03(구조물)/04(사다리)/05(설치물)/06(비계)의 정확한 대응은
이번 표본에 해당 인스턴스가 부족해 검증하지 못했다.**

## 클래스 03/04/06/08 추가 조사 (2026-07-06)

사용자가 "안전모만 말고 보호구 착용 전반"으로 범위를 넓혀달라고 요청해서, 나머지
class 코드도 실제 이미지로 확인했다:

- **03, 04**: 우리가 다운로드한 촬영지(반도체클러스터, S2-N1401/1402/1403)의
  라벨 5,000개 샘플에서 **단 한 건도 발견되지 않음**. 다른 촬영지(화물터미널E/E2,
  이미지 미다운로드) 라벨에만 존재하는 것으로 추정 — **이 촬영지에서는 학습에
  쓸 수 없다(데이터 자체가 없음).**
- **05**: bbox가 사람의 다리/발 부분을 감쌈 → **안전화(safety shoes)로 추정**
  (`results/figures/ppe_class_01_05_sample.png`). 1,420건으로 비교적 흔함.
- **06**: bbox도 다리/발 부분(05와 유사) → 05와 구분이 애매함, 40건뿐으로 드묾
  (`results/figures/ppe_class_01_06_sample.png`). **신뢰도 낮음.**
- **08**: bbox가 헬멧과 다른 종류로 보이는 어두운 색 모자/캡 부위 → 07(흰 안전모)과
  다른 무언가로 추정되나 확신 없음, 13건뿐으로 매우 드묾
  (`results/figures/ppe_class_01_08_sample.png`). **신뢰도 낮음.**

## 이번 작업에 실제로 쓰는 것

06/08은 너무 드물고(40건, 13건) 시각적으로도 확신이 낮아 제외했다. 최종적으로
**신뢰도 있게 확인되고 개수도 충분한 4개 클래스**를 사용한다:

| YOLO class_id | (middle, class) | 이름 | 학습 데이터 내 개수(21,037프레임 기준) |
|---|---|---|---|
| 0 | (01, 07) | helmet(안전모) | 2,175 |
| 1 | (01, 02) | vest(안전조끼) | 1,034 |
| 2 | (01, 01) | harness(안전벨트/하네스, 추정) | 2,177 |
| 3 | (01, 05) | safety_shoes(안전화, 추정) | 1,420 |

"사람" 클래스는 이미 Phase 1의 YOLO11n(COCO 사전학습)이 갖고 있으므로 이 PPE
모델에서 별도로 만들 필요가 없다 — 간접 연결(indirect) 방식대로 (사람 bbox,
Phase 1) + (보호구 bbox, 이번 모델)을 IoU로 매칭해서 매칭 안 된 사람을
"미착용"으로 판정하는 구조(`src/ppe_detection/`, 아직 미구현).

## 신뢰도

- 2프레임(1개는 단일 클래스, 1개는 8개 클래스)만으로 확인한 best-effort 추론이다.
- `class` 코드가 middle_classification과 무관하게 전역적으로 유니크한지, 아니면
  middle_classification마다 별도 네임스페이스인지도 확인 안 됨(현재는 후자로 가정).
